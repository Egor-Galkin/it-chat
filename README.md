# MAX Chat Client

Веб-приложение для отправки и получения текстовых сообщений через сервис Green-API. Интерфейс разработан с упором на минимализм, производительность и соответствие современным стандартам веб-мессенджеров.

## Демо-версия

Приложение развернуто и полностью функционально. Вы можете протестировать его по ссылке:
[https://it-chat-ten.vercel.app/](https://it-chat-ten.vercel.app/)

## Возможности

- **Авторизация** с использованием учетных данных Green-API (`idInstance`, `apiTokenInstance`).
- **Инициация нового чата** по номеру телефона получателя.
- **Отправка текстовых сообщений** через REST API.
- **Получение сообщений в реальном времени** с использованием технологии HTTP API (Long Polling).
- **Автоматическая очистка очереди** уведомлений для предотвращения дублирования данных.
- **Устойчивая обработка** различных форматов текстовых сообщений (стандартные и расширенные).

## Стек технологий

- **React 18** (функциональные компоненты, хуки).
- **Vite** (сборка и локальный сервер разработки).
- **Fetch API** (взаимодействие с сервером).
- **CSS** (кастомные стили без использования тяжелых сторонних UI-библиотек).

## Требования к окружению

- Node.js версии 18.x или выше.
- Менеджер пакетов npm, yarn или pnpm.

## Установка и локальный запуск

1. Клонируйте репозиторий:
   ```bash
   git clone <repository-url>
   ```

2. Перейдите в директорию проекта:
   ```bash
   cd it-chat
   ```

3. Установите зависимости:
   ```bash
   npm install
   # или
   yarn install
   # или
   pnpm install
   ```

4. Запустите сервер разработки:
   ```bash
   npm run dev
   ```

5. Откройте в браузере адрес, указанный в терминале (обычно [http://localhost:5173](http://localhost:5173/)).

## Настройка инстанса Green-API

Для корректной работы приложения необходимо выполнить следующие действия в консоли Green-API:

1. Создать новый инстанс и авторизовать его, отсканировав QR-код в мобильном приложении.
2. Перейти в настройки инстанса.
3. Убедиться, что поле **"Адрес отправки уведомлений (URL)"** (`webhookUrl`) абсолютно пустое.
4. Включить переключатели:
   - Получать уведомления о входящих сообщениях и файлах.
   - Получать уведомления о сообщениях, отправленных с телефона.
5. Сохранить изменения и подождать 1–2 минуты до их применения на сервере.

## Архитектурные особенности реализации

### Обход CORS при разработке
В файле `vite.config.js` настроен прокси-сервер, который перенаправляет запросы с префиксом `/api` на `https://api.green-api.com`. Это позволяет избежать ошибок Cross-Origin Resource Sharing на этапе локальной разработки без необходимости использования браузерных расширений.

### Механизм Long Polling
Получение сообщений реализовано через рекурсивный вызов `setTimeout` после завершения предыдущего запроса `ReceiveNotification`. Это предотвращает наложение запросов друг на друга при нестабильном сетевом соединении.

### Управление очередью
Каждое полученное уведомление немедленно удаляется из очереди методом `DeleteNotification` в соответствии с документацией Green-API, что гарантирует строгий хронологический порядок (FIFO) и отсутствие дубликатов.

### Защита состояния
Перед добавлением нового сообщения в стейт React выполняется проверка на наличие сообщения с таким же `idMessage`, что исключает рендеринг дубликатов.

## Ограничения и известные особенности

### 1. Ограничения бесплатного тарифа (Ошибка 466)
На тарифном плане **"Разработчик" (Developer)** сервис Green-API устанавливает строгое ограничение: взаимодействие разрешено не более чем с **3 уникальными чатами** в течение календарного месяца. 

При попытке отправить сообщение четвертому уникальному контакту сервер вернет HTTP-статус **466 (Quota Exceeded)**. Приложение корректно перехватывает эту ошибку и выводит информативное сообщение пользователю, не прерывая работу интерфейса. 

> Удаление инстанса не сбрасывает данную квоту.

### 2. Решение проблемы CORS в продакшен-среде
При деплое приложения на хостинги браузер может блокировать прямые запросы к API из-за политики CORS (отсутствия заголовка `Access-Control-Allow-Origin` на стороне Green-API). 

В данном проекте эта проблема решена на уровне конфигурации хостинга: файл `vercel.json` настроен как edge-прокси, который прозрачно перенаправляет (rewrites) все запросы с префиксом `/api/` на `https://api.green-api.com/`. Это позволяет приложению полноценно и безопасно работать в продакшен-среде (на Vercel) без необходимости развертывания отдельного бэкенд-сервера.

### 3. Специфика чата с самим собой (Saved Messages)
При отправке сообщений в чат **"Избранное"** некоторые мессенджеры присваивают сообщению системный идентификатор чата, отличный от стандартного формата `[номер@c.us](mailto:номер@c.us)`, а также могут классифицировать его как исходящее (`outgoingMessageReceived`). 

Приложение содержит гибкую логику проверки типов сообщений, позволяющую отображать такие уведомления, однако для полноценного тестирования двусторонней связи настоятельно рекомендуется использовать два различных номера телефона.
